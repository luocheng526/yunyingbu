# 什么时候必须升壳

浏览器把带 `?v=壳版本` 的文件当成一天不可变缓存。**只有这些文件跟壳版本绑在一起：**

| 要显示的更新 | 要不要升壳 |
|---|---|
| 侧栏增减/改名/改路径（`nav-items.js` + `nav.js`） | **要。** 只有主框架能改。 |
| 顶栏、页签、强制刷新、`nav.js` 行为 | **要。** |
| `layout.css`、logo、标签图标 | **要。** |
| `pages.js` / `middleware.js` 出的 HTML 壳（`renderAppShell`） | **要。** 两文件成套。 |
| `public/shared/modules/<自己>.js` 里的页面内容 | **不要。** 不再带壳版本号，硬刷新就会拉新文件。 |
| 只改 `src/modules/<自己>/` 的 API | **不要升壳。** 改了 src 的单勾重启即可。 |
| 登录页 `login.html` / `login.css` | **不要找主框架升壳。** 归个人中心，登录页不进壳。 |

## 业务对话框怎么通知主框架

不要自己改 `nav.js` / `nav-items.js` / `pages.js` / `middleware.js`。

要加、删、改子菜单或页签规则时：

1. 先交自己的内容单（只带自己目录和 `shared/modules/<id>.js`）。
2. 摘要第一句写：`请主框架：沈子晗侧栏删掉商品成长`（换成你的原话）。
3. 给用户一句去**主框架对话框**粘贴，例如：`请主框架按章程升壳：……`

主框架看到「请主框架」或用户把这句话转过来，就自己改壳、升 `SHELL_ASSET_VER`、交主框架单。不要等用户再说「你升一下壳」。

只改了自己的 `shared/modules/*.js`：**不要**写请升壳，不要叫用户来喊主框架。

## 主框架每次对话先做

登录线上看 `/api/releases` 最近成功/待上线单。摘要含「请主框架」、或明显是加删改子菜单的，立刻改壳并交单。不要把升壳推回给用户。
